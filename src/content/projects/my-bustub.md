## 项目简介

CMU 15-445/645《数据库系统导论》配套的 BusTub，用 C++ 从零实现数据库引擎的核心部件。这里归纳我做过的三个重点 Project：缓冲池管理器、B+ 树索引、外部哈希连接，每一块都对应引擎的一条核心链路。

## 项目一：缓冲池管理器（ARC 淘汰策略）

**为什么要自己写缓冲池**：直接映射页缓存，省去 Linux 页缓存从内核态到用户态的一次多余拷贝，提速度、降空间浪费；数据库自定义页大小不一定是 4KB，与系统页缓存不一致；自定义淘汰策略能保证正在使用的页不被刷盘；还能控制刷盘顺序——必须保证日志（redolog）先落盘再刷数据。

- **ARC 类**：维护 T1/T2/B1/B2 四条链表 + unordered_map 快速更新位置，链表存帧 id（从新到旧）；维护帧 id → 帧状态（evictable / pincount / page_id）映射。被固定（pincount > 0）的条目跳过；若所需淘汰侧（mru_/mfu_）全被固定，则从另一侧选受害者并移入对应幽灵列表（mru_ghost_ / mfu_ghost_）。接口：更新、驱逐、删除、设置是否可驱逐。
- **BufferPoolManager**：帧状态与数据的 vector、页帧映射表、空闲帧 list、ARC 淘汰器、磁盘调度器。从磁盘读数据到对应页映射的帧头（内部 vector\<char\> 直接在内存修改），换出时再刷回磁盘。
- **disk_schedule**：由 BPM 创建「写盘（刷盘）/ 读盘」两种请求加入任务队列，实现耗时任务异步化、提高接口响应；分 k 个任务队列由 k 个线程各执行自己的队列——保证相同页任务串行、不同页任务并行。

**性能优化**：缓存命中率与磁盘 IO 次数——从 LRU-K 升级到 ARC；读写延迟——写操作异步执行（创建 disk_request 时 promise + future 让前台继续跑，后台写），响应速度大幅提升。

## 项目二：B+ 树

- 继承 page 基类实现内部页、叶子页和头部页；Context 类保留查找过程中的锁上下文。
- **查找**：先取头部页读保护、拿到根节点页 id 后释放；根节点加读保护后二分查找走向子节点，先加子节点读保护再释放当前节点——蟹型锁策略一路到叶子读取。
- **插入**：一路获取路径上的写锁，强转内部页/叶子页加入 Context 保存，直到叶子；溢出时旧页保留拆分点左侧指针、新页保留右侧指针，父节点插入新键并处理**递归上溢**。
- **删除**：叶子删除后低于下限触发**下溢**（叶子作根除外），借不到兄弟节点就合并，父节点内部键减少导致**递归下溢**。
- **性能优化**：取子节点前先判断其是否可能上溢/下溢，不可能就先取再释放路径上所有写锁；把路径写锁改为读锁、只在最后叶子节点加写锁，降低并发冲突，确需递归处理时才回滚改加写锁。

**踩坑记录**：B+ 树迭代器初版把叶子页保护写死，导致需要迭代器的查询里写操作无法获取该叶子页写锁。解决：初始化迭代器不拿锁，调用解引用后再获取页保护。

**死锁处理**：单节点时既是叶子又是根，满则分裂出两个叶子再产生内部节点，需要改头部页的根 id。因"可能溢出的页不释放父节点"策略，同时持有信息页与原根页锁进行分裂，改根 id 时再次获取信息页锁造成**循环等待**。解决：信息页与根节点页之间不采用"先取子后放父"的策略。

## 项目三：外部哈希连接

- 查询优化：嵌套循环连接转外部哈希连接，递归提取逻辑/运算符表达式，处理多条件连接。
- **自定义外部页**：存放大表连接时内存放不下的分区数据（数据倾斜时一个分区多个磁盘页）；页内只存元组个数 + 序列化元组内容。
- **分区管理类**：记录每个分区管理哪几个磁盘页，便于构建分区哈希表。
- **外部哈希连接类**：分区哈希 + 探测哈希两个函数、两个分区管理 vector；从左右子计划 `next()` 取元组分区，对右子计划按分区构建探测哈希表；`next()` 对每个分区探测，批次满返回，直到无匹配。

**待优化**：同分区数据多时哈希冲突严重 / 构建的哈希表内存放不下——可递归再哈希一遍并做标记，防止分区内元组过多导致哈希表内存巨大。

**可扩展对比（三种连接）**：索引嵌套循环连接——外表小、内表大且有索引，内表免全表扫描，内存低速度快 O(n log n)，支持范围查询与有序输出，大表不合适；哈希连接——大数据量下 O(N+M)、适合大表 join 大表、无需索引，但只支持等值 join、需缓存整张 build 表，外部页会产生磁盘临时文件、IO 增长；归并连接——有序遍历顺序 IO、输出有序，但两表都需按 join key 排序，适合已经有序的两张表。

## 价值

亲手把存储、索引、执行三层各实现一遍，才真正理解"一条 SQL 是怎么跑起来的"。这套课是数据库领域最经典的实践课。
