## 项目简介

一个分布式智能云存储 + RAG 知识库系统：三层微服务架构（网关层 / 元数据层 / 存储层）各自独立水平扩展，网关用一致性哈希做节点负载均衡，存储节点自动感知上下线，并在其上实现了 LLM 知识库问答。

## 存储节点如何水平扩展（三层感知）

**核心问题**：如何让网关实时感知存储节点上下线？传统方案有痛点——静态配置要改配置重启、运维成本高；纯轮询只能探测已配置节点、无法新增节点。

**方案**：「主动通知 + Watch 推送 + 健康检查兜底」三层机制：
1. **节点生命周期管理**：存储节点启动时向 RaftKV 注册、优雅退出时注销，触发元数据节点的回调；
2. **秒级感知**：元数据节点通过 RaftKV 的 Watch 机制监听节点变化，主动推送给所有在线网关，网关实时更新一致性哈希环；
3. **30 秒健康检查兜底**：网关定期通过 RPC 探测所有节点，对无响应节点主动移除，防止 Watch 事件丢失。

这套方案实现秒级节点上线感知，极端情况下也保证最终一致性。

## 三层微服务架构

- **网关层（libhv HTTP）**：对外提供 RESTful API，负责请求路由、负载均衡、流式响应；Nginx 做网关负载均衡。
- **元数据层（RaftKV）**：存储集群元数据、提供服务发现、维护节点状态，Raft 协议保证高可用。同时充当配置中心：节点上下线时给元数据节点发通知，元数据节点监听后推送给网关维护哈希环；网关上线时也要向元数据节点注册，转发消息时才能找到存活的网关地址。
- **存储层（mrpc RPC）**：负责文件 IO、RAG 索引、向量检索，节点完全对等，通过一致性哈希分发。

三层完全解耦的无状态服务，各自独立水平扩展，集群支持线性扩容。

## LLM 知识库问答（上传即索引，提问即检索）

- **上传阶段**：文件到达存储节点后自动做 chunk 切分 → 向量化 → BM25 索引 → LLM 生成摘要，全量落盘——一次上传，全部落库。
- **路由阶段**：网关拉取所有节点的文件摘要，通过 LLM 做意图识别，动态路由到目标知识库，确保只查询特定的一个库。
- **检索阶段**：目标节点执行 Annoy 向量 + BM25 **混合检索**，返回最相关的文档片段。
- **回答阶段**：网关拼接上下文，调用通义千问流式返回（SSE）。

这套架构让知识库容量随存储节点线性扩展，同时保证检索精度。

## 一致性哈希

一致性哈希用于将数据/请求均匀映射到分布式节点，大幅减少节点上下线时的重映射数据量。普通哈希（`hash(key) % 节点数`）在节点增减时分母改变，几乎所有 key 都会重新映射，造成缓存失效、数据迁移与雪崩风险。

| 策略 | 核心能力 | 数据粘性 | 节点扩缩容影响 | 适用场景 |
| --- | --- | --- | --- | --- |
| 轮询 | 简单负载均衡 | 无 | 无数据迁移 | 无状态接口、纯流量转发 |
| 最少连接 | 动态负载均衡 | 无 | 无数据迁移 | 请求耗时差异大的无状态服务 |
| 一致性哈希 | 哈希路由 + 均衡 | 强粘性 | 仅少量数据迁移 | 分布式缓存、分库分表、有状态分片 |
