> 2026 年 4 月找实习的面经整理。本篇为海康威视 C++ 实习一面。

## Q1：Windows 上开发的程序到 Linux 无法正常运行，可能的原因？

**操作系统 API / 系统调用差异**（最核心）：两平台的 API 体系不同，依赖 Windows 特有的 API 或系统调用的代码直接无法编译或运行。

**文件系统差异**：
- **路径分隔符**：Windows 用 `\` 反斜杠、Linux 用 `/` 正斜杠，硬写死路径会导致文件找不到；
- **大小写**：Windows 文件默认大小写不敏感，Linux 严格区分大小写，`Test.cpp` 和 `test.cpp` 在 Linux 是不同文件；
- **换行符**：Windows 是 `\r\n`、Linux 是 `\n`，文本文件在两端解析会出问题。

**编译差异**：一些特有的编译语法跨平台无法识别；库文件后缀不同（如 `.lib`/`.dll` vs `.a`/`.so`）导致链接错误；有些包是平台专属的，跨平台没有替代。

**字符编码差异**：Windows 常用 GBK、Linux 是 UTF-8，导致中文日志、配置、字符串乱码、解析失败。

## Q2：C++ 中 `optional` 和 `variant` 有什么区别？

- **`optional<T>`**：**不一定有值**，并且**只能存一种类型**——表示"值的存在性"（有/没有）；
- **`variant<T1, T2, ...>`**：**一定有值**，但**值的内容类型不确定**——表示"值的多态性"（是众多类型中的哪一种）。

一个表示存在性，一个表示多态性，语义完全不同。

## Q3：Debug 模式能跑、Release 模式却报错，可能的原因？

Debug 不优化、带调试信息、内存初始化、栈检查严格；Release 开 O2 优化、去掉安全检查、内存不初始化。本质是：**Debug 的安全机制掩盖了 bug，Release 去掉保护后暴露**。

- **未初始化变量**：Debug 模式会自动填 0，不会乱码；Release 模式下是随机垃圾值，可能导致随机跳转、崩溃；
- **编译器优化**：Release 的 O2 优化可能导致无效代码删除、指令重排，某些依赖顺序执行的逻辑（尤其多线程）优化后产生未定义行为；
- **多线程问题**：Debug 跑得慢，缩小了锁竞争；Release 跑得快，死锁和竞争可能加剧；
- **宏定义问题**：代码里写了 Debug 专属的宏定义代码段，模式切换后这些代码不执行或多余执行。

## Q4：熟悉的检查内存泄漏的工具？

**GDB**：Linux 下 C++ 标准调试工具，主要用于分析程序崩溃、查看调用栈、分析 core dump 文件，是定位复杂问题的基础工具。

**ASan**（AddressSanitizer）：内置在编译器中，编译时开启即可，快速检测栈缓冲区溢出、use-after-free、重复释放、野指针、访问未初始化内存、内存泄漏等内存错误：

```bash
g++ -fsanitize=address,leak,undefined ...
```

- 栈缓冲区溢出（数组越界）会显示崩溃栈；
- use-after-free 会显示在哪里 UAF、哪里释放、哪里分配的调用栈。

**要点**：开发阶段必开，但**上线要关闭**——因为会变慢、耗内存。
