## 一面 · 推理框架的两大步骤？

- **Prefill 阶段**：对提示词进行 token 转换，**并行计算**，得到第一个输出的 token 并缓存所有 KV 对。由于这一刻的并行计算能充分利用 GPU 计算单元，速度很快，瓶颈在于从显存到 GPU 的搬运——是 **IO 密集型**的运算。
- **Decode 阶段**：**逐个 token 生成**，复用前面缓存的 KV，属于**计算密集型**。

## 二面 · Wireshark 怎么抓一个本机发出的 DNS 包？

1. 管理员启动 Wireshark → 选择上网网卡 / 回环 lo；
2. 手动 ping 一个还没缓存的域名，产生 DNS 查询；
3. 使用过滤表达式：

```
dns and ip.src == 本机IP and dns.flags.response == 0 and dns.qry.name contains "目标域名"
```

`dns.flags.response == 0` 表示只过滤请求（非响应）报文。

## 二面 · 容器突然无法访问宿主机数据库的排查思路？

前提：容器是 bridge 模式，MySQL 运行在宿主机本地。先记住：**`docker exec` 基于宿主机本地的 docker.sock 通信，不依赖容器网络与网卡**——即使容器网卡损坏、无 IP、网络完全不可用，依旧能正常进入容器排查。

排查链路：

1. **先本地 telnet 一下 3306 端口**，确认服务是否正常；不正常就是数据库问题，重启；
2. **进入容器内部**：`ip addr` 检查自身网络状态、IP 是否正常，排查容器网桥路由、网络模式异常，必要时用 host 网络模式验证；
3. **ping 宿主机 IP** 看网络是否连通（注意要用**网桥地址而不是回环**）；ping 不通可能是防火墙问题，修复容器宿主机连通性后再检查 3306 是否连通；
4. 如果连通但连接不上，可能是**宿主机数据库只监听 127.0.0.1**——修改监听地址到全部网段；
5. 还不行可能是**数据库账号远程访问权限未打开**，需要授权；
6. 最后排查**容器内的数据库连接配置**是否有问题。

## 二面 · WebSocket 和 HTTP 的区别？WebSocket 是怎么升级过去的？

**区别**：HTTP 是单向问答模式，服务端不能主动推送；WebSocket 基于 TCP 长连接、**全双工通信**，双方可实时互发数据，传输开销更小（头部小、数据流快），适合实时业务。

**升级过程**：WebSocket 通过 HTTP 握手升级实现——客户端携带 `Upgrade`、`Connection`、`Sec-WebSocket-Key` 等头部发起 HTTP 请求；服务端校验合法后返回 **101 Switching Protocols**，完成协议切换；原有的 TCP 连接持续复用，后续基于 WebSocket 帧进行双向长连接通信。
